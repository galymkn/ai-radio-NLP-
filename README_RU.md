# NewsRadio — реализация MVP

Конвейер: RSS / Telegram → сохранение текстов → embeddings (SBERT) → кластеры событий → LLM-редактор (по умолчанию бесплатный Gemini) → отдельная проверка предложений → подготовка текста → TTS → MP3 → веб-плеер и непрерывный поток `/stream`.

## Быстрый запуск демо

Нужны Python 3.10+ и ffmpeg (`brew install ffmpeg` на macOS).

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
python -m newsradio demo
```

Откройте http://localhost:8000. Демо использует синтетические новости, локальный hash-encoder и извлечение предложений. **Звук — тестовый тон, не речь.** Создаёт `data/demo/run-…/episode.mp3` и JSON с текстами, временными отметками и ссылками. `--no-serve` создаёт файлы и завершает процесс. Каждый запуск получает новый каталог `run-…` (путь печатается в терминале), поэтому истёкшие клипы и история предыдущей репетиции не мешают показу. Старые выпуски сохраняются; их можно удалить вручную.

Для речевого демо без LLM: `python -m newsradio demo --tts edge` (интернет). Для обеих реальных интеграций: `python -m newsradio demo --editor gemini --tts edge` (ключ Gemini и интернет).

## Бесплатный режим: Gemini

Редактор и проверка фактов по умолчанию работают на Google Gemini (`editor.backend: gemini`) через бесплатный ключ из Google AI Studio.

```bash
pip install -e '.[embeddings,dev]'
# в .env: GEMINI_API_KEY=ваш_ключ
python -m newsradio check-llm   # один тестовый запрос: проверяет ключ и модель
python -m newsradio run
```

- Модель задаётся в `config.yaml` (`editor.model`, по умолчанию `gemini-3.5-flash`) или переменной `EDITOR_MODEL`. Список бесплатных моделей и лимиты своего проекта смотрите в Google AI Studio.
- На каждый сюжет уходит 2 запроса (текст + проверка). Чтобы не выходить за бесплатные лимиты: `max_edits_per_cycle: 4`, пауза `min_seconds_between_calls: 6` между запросами, свой дневной потолок `max_calls_per_day: 200` (счётчик сбрасывается при перезапуске), цикл раз в `poll_seconds: 300`.
- Ответ HTTP 429 (лимит) не считается ошибкой сюжета: обработка ставится на паузу до следующего цикла, попытки сюжета не тратятся. Состояние видно в `/api/status` → `worker.editor` (`last`, `paused`).
- На бесплатном тарифе Google может использовать запросы для улучшения своих продуктов. Для публичных новостей это допустимо; приватные данные через этот режим не отправляйте.

## Живой эфир без пауз

- В `run` сбор новостей идёт раз в `poll_seconds`, а редактор работает отдельным непрерывным циклом: пока звучит один клип, следующий сюжет уже пишется, проверяется и озвучивается. `max_edits_per_cycle` действует только для `cycle` и `demo`.
- `wheel.repeat_stories: false`: каждая новость звучит один раз. Когда новых нет, плеер ждёт следующую и показывает это; повтор — только если слушатель сам выбрал новость в списке «Stories on air».
- `editor.workers: 2`: два редактора пишут сюжеты параллельно, чтобы новые клипы появлялись быстрее, чем звучат. Квота Gemini у них общая.
- `wheel.fill_silence` действует только при `repeat_stories: true`: тогда вместо ожидания сразу повторяется самый давно звучавший клип.
- `editor.priority_sources`: сюжеты с этими источниками обрабатываются первыми (по умолчанию Astana Times и @tengrinews). `wheel.boost_categories`: эти категории звучат чаще.
- `editor.script_words: "120-180"` — длина текста (≈ 45–70 с). Если в источниках мало фактов, модель пишет короче, а не дополняет.
- Дневной лимит: каждый сюжет = 2 запроса к LLM. При `max_calls_per_day: 200` это около 100 сюжетов в день; дальше эфир повторяет готовые клипы. Поставьте значение чуть ниже дневного лимита своей модели в Google AI Studio.

## Реальный запуск

```bash
pip install -e '.[embeddings,postgres,telegram,dev]'
cp .env.example .env
# Заполните GEMINI_API_KEY (или ANTHROPIC_API_KEY при editor.backend: claude). При необходимости EDITOR_MODEL.
python -m newsradio run
```

Модель embeddings скачивается при первом запуске. Язык задаётся в `config.yaml`: например, `language: ru` и `tts.voice: ru-RU-DmitryNeural`. Начальный список содержит 10 источников (5 RSS + 5 публичных Telegram); доступность и редакционную пригодность каждого проверьте перед эфиром.

Postgres: задайте `DATABASE_URL`. Без него используется SQLite. Новая база и таблицы создаются автоматически; автоматической миграции данных из SQLite нет. Для запуска с Postgres через Docker:

```bash
# В .env задайте POSTGRES_PASSWORD — длинный пароль без URL-спецсимволов.
docker compose up --build
```

Compose открывает порт только на localhost. Поддерживается один экземпляр приложения/worker; распределённые блокировки и несколько worker пока не реализованы.

Telegram по умолчанию читается через web preview. Для MTProto задайте `ingest.telegram_backend: telethon`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION` (заранее авторизованная StringSession). Worker не запрашивает телефон и коды входа. Сессия — секрет; храните её только в `.env`.

## Что доработано

- Postgres через psycopg, сохранение исходных заголовков/текстов до очистки в `raw_items` для принятых статей; SQLite для демо.
- Telethon collector с ограничением истории, обработкой ошибок по каналам и отключением клиента.
- Одинаковые заголовки разных источников сохраняются для кластеризации и подсчёта источников; повтор URL не добавляется.
- Верификация требует один явный boolean-вердикт для каждого предложения. Пропуски/дубли/ошибки отклоняют публикацию, а не разрешают непроверенный текст.
- Источники обозначены как недоверенные данные в промптах.
- `tts.normalize: false` по умолчанию: исходные числа, валюты, время и сокращения поступают в Edge без изменений. Ограниченный нормализатор en/ru можно включить явно (например, для Kokoro); русская морфология в нём не исправлена.
- Экспорт цельного MP3 из активных клипов с JSON-манифестом и URL источников: `python -m newsradio episode --output data/episode.mp3`.
- В поставляемом `config.yaml` включена радиоротация (`wheel.repeat_stories: true`). Для выдачи по одному разу задайте `false`. В демо повтор включён с нулевым cooldown; рабочая конфигурация сохраняет паузу между повторами, поэтому короткая очередь может временно простаивать. История выдачи веб-плееру сохраняется в БД между перезапусками; новый вариант сюжета доступен снова. Это память **выдачи**, а не подтверждение прослушивания. `/stream` сохраняет историю только в рамках соединения.
- Worker повторяет попытку после ошибки инициализации; статус последнего цикла доступен в `/api/status`. Ошибки обработки сюжета учитываются в БД: `editor.max_attempts: 3`, экспоненциальная пауза от `retry_backoff_seconds: 120`, затем статус `failed`. Новые статьи не сбрасывают исчерпанный лимит; ручной сброс: `python -m newsradio retry-failed`. Успешная обработка очищает счётчик.
- Скрипты оценки и длительного наблюдения.

## Проверка и защита

```bash
pytest -q
python -m newsradio.evaluate fixtures/annotations.example.json
python scripts/soak.py --hours 24 --output soak.jsonl
```

Экспорт реальных статей для разметки:

```bash
python -m newsradio export-labels --limit 50 --output data/annotations.json
python -m newsradio.evaluate data/annotations.json
```

Экспорт включает последние 50 кластеризованных статей, тексты, ссылки, прогноз кластера и пустой `gold_story`, предложения клипов с источниками и пустым `supported`. Заполните одинаковый `gold_story` для сообщений об одном событии, `supported` — true/false по первоисточникам. Пустые значения исключаются из метрик и отдельно подсчитываются. Это выборка последних статей, не случайная репрезентативная выборка.

Первый старт клипа фиксируется отдельно от выдачи: веб-плеер вызывает `/api/started` по событию `playing`; `/stream` отмечает отправку первого фрагмента. Повтор не меняет первую дату. Это клиентское подтверждение старта / отправка сервером, не доказательство слышимого воспроизведения. Время публикации — самая ранняя известная дата источника сюжета, уже присутствовавшего при создании клипа. В API нет аутентификации: эти события предназначены для локального демо, не для доверенной публичной аналитики.

Файл `fixtures/annotations.example.json` — синтетический пример формата, не результат исследования. Для отчёта разметьте пары/кластеры статей (`gold_story`), проверяйте каждое предложение по источникам (`supported`) и запишите реальные `published_at` / `broadcast_at` в Unix seconds. Инструмент считает pairwise precision/recall, долю неподтверждённых предложений и p50/p95 задержки. При отсутствии данных возвращается null, а не выдуманная оценка. Автоматический LLM fact-check не заменяет ручную разметку.

`soak.py` наблюдает HTTP-статус и состояние worker; это не нагрузочный тест множества слушателей. Суточный прогон следует выполнить отдельно на целевой машине с реальными источниками. Проверьте не только HTTP 200, но и свежесть `worker.last_success`, ошибки и рост числа клипов.

Сценарий демо на защите:
1. Запустить демо, показать статьи, кластеры и очередь.
2. Показать текст выпуска и ссылки в `episode.json`.
3. Повторить цикл — повторные URL не создают новых клипов.
4. Показать тесты отказа при неполной проверке фактов.
5. Для речевого показа заранее подготовить выпуск с `--tts edge`.
6. Представить ручную оценку и журнал суточного прогона, когда они будут получены.

## Границы текущей версии

Проверка LLM не гарантирует отсутствие галлюцинаций. Hash-encoder предназначен только для демо; качество семантической кластеризации нужно измерить на ваших языках и источниках. Редактор/проверка остаются эвристическими для определения новых фактов. Не реализованы retention старого аудио/истории, мониторинг с оповещениями, полноценная миграционная система и многопроцессное исполнение.

Документация интеграций: [psycopg](https://www.psycopg.org/psycopg3/docs/basic/usage.html), [Telethon](https://docs.telethon.dev/en/stable/modules/client.html), [Claude models](https://platform.claude.com/docs/en/models/overview).
